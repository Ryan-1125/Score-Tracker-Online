# 联机使用与本次改进

顶部操作顺序为骰、主题、结、清；普通成员不显示清。

## 房间与邀请

进入房间后，点击绿色房间号复制号码；房间管理里的“邀请朋友”复制邀请链接。链接自动填写房间号，加入仍需设置昵称。有密码时在联机入口填写密码。

房主在房间管理中设置密码、取消密码、锁定加入。空密码表示保留原密码，取消密码需单独操作。锁定限制新成员，不影响原设备恢复席位。密码使用加盐摘要保存，不向成员广播。

本地邀请链接只适用于可以访问该电脑的设备。在同一 Wi-Fi 下使用电脑的局域网地址；localhost 链接只能在该电脑使用。公网邀请需要部署服务。

## 身份、权限与离线

成员列表标记“我”。普通成员可从自己转出积分，房主可代记、撤销、移交与移出成员。移出成员保留已有账目并使原席位凭证失效。

断线自动重连，暂时无法写入；正在填写的分数保留。短暂的确认超时自动用同一请求编号重试一次，服务端防止重复记账。多人记分由服务端依次处理；撤销校验最新记录编号，避免撤销错笔。

房主离线满两分钟后，其他在场成员可在房间管理中接管。房主重新连接时仍沿用原身份；如果已被接管，则作为普通成员继续。

## 多局与数据

“结”查看本局结果及导出图片。房主选择“开始下一局”后保存本局积分与完整明细，归零进入新局。房间管理中“往局记录”查看每局明细和已完成局的累计积分。

房间保留至房主解散，不自动按时间删除。清零只清当前局，解散删除整个房间，包括往局。SQLite 持久保存，服务重启可恢复。

更新部署前运行 `npm run backup`，备份写到 data/backups。恢复时停止服务，保留当前数据库副本，再用备份替换 data/rooms.db。备份包含席位凭证，勿上传公开仓库。

## 验证与后续

运行 `npm test`，覆盖身份、权限、防重复、重连、密码、锁定、移出、多局和房主接管。前端保留圆形头像和胶囊按钮，头像增加昵称首字与 24 个图案，并按身份生成不同底色。

微信小程序和公网部署仍需单独实现、配置和真机验证；当前网页不能直接作为已上线小程序。后续可拆分通信适配层和页面模块，增加独立小程序客户端。当前无自动备份调度、账号体系及跨房间永久战绩。

## 可以积累的项目经验

- 联机权限必须在服务端判断，隐藏按钮仅改善使用体验，不能代替权限校验。
- socket 连接会变化，玩家身份要独立保存；恢复凭证和连接编号不应广播给其他成员。
- 网络确认丢失时，重试必须使用同一个请求编号；记分请求编号持久保存，避免重连或服务重启导致重复入账。
- 多人同时操作时，撤销应带目标记录编号，开始下一局应带局号；服务端拒绝已经过期的操作。
- 成员离开不等于删除账目。已有积分与记录保留，开始下一局后才释放离开成员的当前席位。
- 使用内存数据库和真实 Socket.IO 客户端测试完整流程，可以验证界面点击测试难以稳定复现的并发、权限与断线情况。
- 数据库在线备份要使用数据库的备份接口，不能简单复制正在写入的文件。
