# 本地联机测试指南

## 联机如何工作

浏览器通过 Socket.IO 连接同一台 Node.js 服务。通常使用 WebSocket，必要时可以使用 HTTP 长轮询。记分请求先交给服务端验证成员、权限、整数积分；服务端更新 SQLite 中的房间状态，再广播给房间内的所有浏览器。

房间号是房间入口，不是玩家身份。稳定 playerId 标识玩家，随机 token 证明当前浏览器持有该席位；socketId 只是当前连接，刷新时会改变。仅凭昵称不能恢复别人的席位。

本地模式无需服务端记分；联机模式需要所有人能访问同一台服务。离开 Wi-Fi 后无法继续访问电脑的局域网地址；异地联机需要公网部署服务。

## 方法一：同一台电脑，两标签页

1. 运行 npm start，然后打开 http://127.0.0.1:3000/。
2. 窗口 A 选择联机，昵称填写“甲”，创建房间，记下四位房间号。
3. 新建空白标签页，手动输入同一个地址。不要使用“复制标签页”：复制可能复制席位会话。
4. 窗口 B 选择联机，昵称填写“乙”，输入 A 的房间号，点击加入。不要选择“恢复席位”，那是找回原玩家的入口。
5. A 和 B 都应该显示两位玩家、两人在线。
6. B 点击自己的卡片，再点击甲，输入 10 并确认。两边均应该显示甲 +10、乙 -10，且只有一条记录。

每个标签页的当前席位放在 sessionStorage 中，互相独立。恢复用的凭证另存在该浏览器的 localStorage 中。关闭标签页后，可以从联机页选择原席位恢复；恢复同一个席位会使之前的窗口退出该席位。也可以使用 Edge 和 Chrome，或普通窗口和无痕窗口模拟两个设备。

## 方法二：电脑 + 手机，同一 Wi-Fi

1. 电脑保持服务运行，手机连接与电脑相同的 Wi-Fi。
2. 在电脑 PowerShell 运行 ipconfig，找到当前 WLAN 网卡的 IPv4 地址。不要使用 VMware、蓝牙或断开的网卡地址。
3. 手机访问 http://电脑IPv4:3000/。例如本次检查时 WLAN 地址是 172.27.40.182，因此地址是 http://172.27.40.182:3000/。网络变化后需要重新查看。
4. 电脑创建房间，手机填写另一个昵称和四位房间号加入。
5. 验证同一笔记分能立即在两端显示。

手机不能使用 localhost 或 127.0.0.1 指向电脑：它们代表手机自己。如果电脑能开页面、手机不能，检查 Windows 防火墙是否允许 Node.js 在当前网络接收入站连接；不要直接关闭整个防火墙。校园 / 公共 / 访客 Wi-Fi 可能隔离设备，遇到这种情况换到自己的路由器或允许设备互通的热点再测。

## 验收清单

| 操作 | 预期 |
| --- | --- |
| 成员给自己选出分人，转出 10 分 | 两端同步，积分合计为 0 |
| 成员给其他玩家选出分人 | 提示权限限制；房主可以代记 |
| 刷新任意窗口 | 原昵称、席位、积分和权限恢复 |
| 关闭一个窗口 | 其他窗口显示此玩家离线，积分保留 |
| 从新标签页恢复原席位 | 原窗口收到席位已在其他窗口恢复的提示 |
| 房主撤销最新记录 | 所有人积分与记录同时回退 |
| 进房后修改昵称头像 | 所有人同步；旧记录与撤销仍可用 |
| 房主在“房间”中移交权限 | 新房主获得撤销 / 清零 / 解散权限，旧房主成为成员 |
| 点击“退出房间” | 返回联机选择页；有账目的玩家保留席位与积分 |
| 房主主动退出 | 优先移交给另一位在线玩家，没有在线玩家时选未退出的席位 |
| 离线与主动退出 | 离线保留房主权限；主动退出才触发移交 |
| 恢复退出但仍保留账目的席位 | 返回原积分，不能仅用昵称冒认 |
| 房主清零分数 | 全员同步归零、清空记录；已退出席位释放 |
| 房主选择“解散房间”并确认 | 全员返回联机入口，旧房间无法再次加入 |
| 查看结算 / 导出图片 | 每位成员均可查看，不会清空账本 |

有流水的玩家退出后即使积分为 0 也保留席位，以免丢失历史关联。无积分、无流水的席位退出会删除。房间最多八个席位，包含保留账目的席位。

## 自动测试

运行 npm test。使用内存数据库和随机测试端口，覆盖计分守恒、权限、无效输入、最近请求去重、改名、断线恢复、重复开房拒绝、房主移交、退出恢复、八人上限与解散。不修改 data/rooms.db。

## 当前完成度

已具备日常联机的核心闭环，适合在本机和局域网试用。还不是生产上线版本：待补房间有效期与清理、完整牌局归档、请求版本冲突检测、操作审计、限流、备份监控、微信登录身份以及公网 HTTPS / WSS 部署。重复记分防护保留最近 1000 个请求 ID，不是无限期幂等账本。当前设备凭证会随浏览器数据清理而丢失；没有账号找回功能。
